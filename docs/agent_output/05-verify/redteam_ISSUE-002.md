## 2. Bypasses found

### Bypass via unsecured sibling service (report-service, sheduler-service, department-service)

**Severity:** Critical

`employee-service` is the only module in the fix that gained `spring-boot-starter-security`; `report-service`, `sheduler-service` and `department-service` were left exactly as they were before the patch (no security starter in any of their three `pom.xml` files, no `SecurityFilterChain`/`@PreAuthorize` anywhere in their source). An attacker blocked by the new 401 on `employee-service` simply sends the same anonymous request to `GET /api/v1/export` (report-service, `EmployeeReportController.java:25-39`), `GET /api/v1/employee` (sheduler-service, `EmployeeSchedulerController.java:18-21`) or `GET /api/v1/department/salary/{minSalary}` (department-service, `DepartmentController.java:39-44`) and receives the full payroll/employee dataset with no credential. This is exactly the CWE-306 anti-pattern the catalog names: "Adding authentication only to the specific endpoint named in the issue while leaving structurally identical sibling endpoints open."

### Hardcoded default credential introduced in employee-service (CWE-798)

**Severity:** High

The fix adds `spring.security.user.name=employee-service-admin` and `spring.security.user.password=${EMPLOYEE_SERVICE_ADMIN_PASSWORD:changeit-interim-credential}` to `src/employee-service/src/main/resources/application.properties`. Because the property falls back to a literal default rather than failing to start when the environment variable is unset, anyone with read access to the committed source (this diff included) can authenticate as the service's own admin user with `changeit-interim-credential` in any deployment that does not override the variable — the CWE-798 catalog's canonical approach calls for failing fast on an absent credential instead of this kind of default fallback. It trades the original missing-authentication defect for a second, distinct credential-exposure defect rather than eliminating the first.

## 3. Reasoning

The remediation is real but partial, and partial authentication on a dataset reachable from several services provides close to no confidentiality benefit — the attacker picks whichever service still answers. The default-password fallback additionally trades one weakness for another, since the literal value is in version control.

## Residual risk

- Even once every service enforces authentication, single shared static credentials give no per-principal attribution, which the issue called out as a non-repudiation problem.
