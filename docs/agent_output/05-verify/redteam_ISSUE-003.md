## 2. Reasoning

The catalog anti_pattern for CWE-943 is blacklisting characters rather than changing how the query is constructed; this patch does the latter, which is the canonical approach. Every vector the issue documented depends on the caller influencing query structure, and that capability is gone. In the patched `EmployeeSearchRepository.searchEmployees()`, `name` is bound through `Criteria.where("name").regex(Pattern.quote(name))` (`EmployeeSearchRepository.java:22`) and `department` through `criteria.and("department").is(department)` (`EmployeeSearchRepository.java:25`); both values are handed to the MongoDB driver as Java objects assembled into a `Query`/`Criteria` tree (lines 22-28), never as a JSON string that gets re-parsed. The first vector fails because the caller's quote-and-brace payload is now consumed by `Pattern.quote` as literal regex text inside a single bound field value — there is no surrounding string for the payload to break out of, so it cannot introduce a sibling `$ne` key. The second vector fails for the same structural reason applied to `department`: `.and("department").is(department)` binds the whole string as an equality value, so an operator document embedded in it is never parsed as query syntax, only compared against literally. The third vector fails because nothing in the rewritten method ever constructs a `$where` clause or accepts one from caller input — the only operators present are the ones the code itself calls (`$regex` via `.regex()`), and the caller's string can never occupy operator-key position in the resulting document. Confidence is Medium rather than High only because the module could not be compiled or exercised against a live MongoDB here, so this rests on source reading of the patched method, not on an executed reproduction of the three payloads above.

## Residual risk

- The regex is still unanchored, so a long literal name remains a comparatively expensive collection scan. That is a throughput concern, not an injection route, and it is bounded by the same unbounded-read problem tracked as ISSUE-001.
