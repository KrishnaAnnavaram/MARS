**Why this is environmental, not a test or product defect:** `src/employee-service/pom.xml:18` pins `<java.version>17</java.version>`, but the excerpt below is a Lombok annotation-processing failure under a newer JDK — every symbol Maven reports missing (`getName()`, `getDepartment()`, `getPhoneNo()`, `getAddress()`, `getGender()`, `getEmployeeType()` on `EmployeeServiceImpl.java:115-120`) is a Lombok `@Data`-generated accessor on the `Employee` model, not a method actually absent from the source. When Lombok's annotation processor does not run — which is what happens when the compiler is a JDK newer than the ones Lombok's shipped processor targets — none of its generated getters, setters, constructors or `log` fields exist at compile time, so every call site that depends on them fails with "cannot find symbol" regardless of whether the surrounding logic is correct. This is the same failure mode already recorded in `fix_ISSUE-002.md`'s residual risk section ("the project targets Java 17 and only JDK 25 is installed, so Lombok annotation processing does not run"), and it reproduces identically against the pristine, unpatched source — it is not something this patch introduced.
