## 2. Out-of-scope changes

- WWW-Authenticate header on 401 responses changed from 'Basic realm="Realm"' to 'Basic realm="Realm", charset="UTF-8"' (both 401 probes). Not explained by the plan or the reference pack; 04D reclassified it as an 'expected framework change'.
- Malformed-JSON 400 ProblemDetail body no longer contains "type":"about:blank", and its keys now come out in alphabetical order (detail, instance, status, title). Status, title and detail are unchanged. Not in the plan or the reference pack; 04D reclassified it as expected.
- /actuator/health now carries two new components (livenessState, readinessState) and a "groups":["liveness","readiness"] list, so /actuator/health/liveness and /actuator/health/readiness now exist and are anonymous through anyRequest().permitAll(). Reference pack section 13 covers key reordering and a 'larger' document, but not new endpoints; the plan does not mention them.
- /actuator/metrics meter-name list differs between baseline and final (Boot 4 / Micrometer line). Not explained by the plan or pack; it matters to anything that scrapes metrics by name.
- Request-body strictness loosened (not probed): on the baseline, Spring MVC used the app's own Jackson 2 ObjectMapper (Boot 3.5.0 jacksonObjectMapper is @ConditionalOnMissingBean(ObjectMapper), and the converter takes ObjectMapper). That mapper had FAIL_ON_UNKNOWN_PROPERTIES=true, so a POST/PUT /api/v1/employees body with an unknown property was rejected with 400. On the patched build MVC uses Boot's @Primary JsonMapper with Jackson 3 defaults (spring.jackson.use-jackson2-defaults=false), where FAIL_ON_UNKNOWN_PROPERTIES=false, so the same body is accepted and the extra keys are dropped. Confirmed by running Jackson 2.19.0 vs 3.1.5 with the app's configuration: REJECTED vs accepted.
- Request-body strictness tightened (not probed): Jackson 3 enables FAIL_ON_TRAILING_TOKENS by default (Jackson 2: false), so a body with trailing content after the JSON object (e.g. '{...} {...}'), previously accepted, is now rejected with 400. Confirmed with Jackson 2.19.0 (accepted) vs 3.1.5 (MismatchedInputException).
- The app's JacksonConfig bean is no longer the mapper Spring MVC uses. Boot 4.1.1's jacksonJsonMapper is @Primary @ConditionalOnMissingBean(JsonMapper), the HTTP converter customizer takes a JsonMapper, and the app bean is declared with return type tools.jackson ObjectMapper. So Boot still creates its own JsonMapper and HTTP serialization is governed by it plus spring.jackson.* in application.yml, not by JacksonConfig. Payloads look equivalent today only because application.yml also sets default-property-inclusion: non_null. The plan asked to port the bean 'preserving' its effect, not to move control of HTTP serialization to a different bean. 04D lists this as un-instrumented residual risk.
- H2 web console no longer served (not probed): spring-boot-autoconfigure 3.5.0 contains H2ConsoleAutoConfiguration, but no artifact on the patched 4.1.1 classpath registers an H2 console auto-configuration. 'spring.h2.console.enabled: true' / '/h2-console' in application.yml is therefore inert, and a console reachable anonymously before the patch now returns no console. The plan's application.yml row only covers renamed or removed keys, and H2 console rules are on 04D's out-of-scope list; 04D's report says /h2-console was not probed.

## 3. Reasoning

The collectors' worktree applied the fix diff this run (applied: true in all three bundles), so the full pre-patch vs patched source of all 6 changed files was compared. The mechanical signature diff shows no method-signature changes (objectMapper() and health() unchanged; the regex parser has nothing to say about pom.xml or the Dockerfile), and I did not rely on it. For a VERSION_MIGRATION, every changed file and every before/after probe difference has to trace to the plan's migration request or the reference pack. All six changed files do: five are in the plan's Planned changes table, and EmployeeRepositoryIntegrationTest.java is a test import explained by pack section 4.3 though missing from the plan's table. The runtime evidence does not all trace. I read 04D's baseline and final probe records myself (.github/.pipeline-context/version-migration/issue-001/runtime/{baseline,final}.json). All 19 statuses match and application-owned bodies are equivalent. But the WWW-Authenticate charset parameter, the ProblemDetail 'type' omission and key reordering, the new health components and groups (with their new anonymous endpoints) and the metrics name list are framework-owned changes that neither the plan nor the pack explains. 04D reclassified them as 'expected framework change' and left its own C8 contract constraint unresolved and blocking, so they are not preserved behaviour. Beyond the probes, I checked the Boot 3.5.0 and 4.1.1 class files with javap, scanned the auto-configuration imports and ran a small Jackson 2.19.0 vs 3.1.5 comparison. They show three more observable changes no probe covered: unknown request properties go from 400 to accepted, trailing tokens go from accepted to 400, and the H2 console disappears. They also show that the app's JacksonConfig bean no longer drives HTTP serialization. None of these is judged good or bad here; they are changes the plan does not account for, so the verdict is BEHAVIOR_CHANGED. The patch's Status is Compiled (04D build rounds), and this verdict says nothing about the build.
