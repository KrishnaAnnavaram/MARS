## 2. Reasoning

The finding is CWE-1104: the service ran on an out-of-support platform generation. A bypass would mean the unmaintained Boot 3.5 / Spring 6 line still being selected or reachable, or the migration opening a way around the security boundary it was required to keep. I attempted 11 concrete vectors against the materialized patched source (collectors' worktree applied: true) and my own resolved dependency tree and classpath checks, grounded in the catalog's anti_patterns (property edit overridden elsewhere, pom text verified but resolved tree not, a generation jump treated as a single bump) and in the migration-specific angles: auth filter chain, error contracts, actuator exposure, and rejected/reverted OpenRewrite hunks. None succeeds. All Boot artifacts resolve at 4.1.1; the Java level is moved in every executable descriptor; SecurityConfig is unchanged and its path rules are not weakened by Security 7 defaults; error bodies expose nothing new; rejected hunks did not ship. Two vectors stay uncertain rather than blocked: the new anonymous liveness/readiness health-group endpoints (a small, low-sensitivity widening that the migration introduced) and the fact that the app's own JacksonConfig mapper is no longer the HTTP mapper, so NON_NULL safety now depends on application.yml. Neither undoes the platform move. Confidence is Medium, not High, because the path-variant and mapper-selection vectors were reasoned from the code and the Boot 4.1.1 class files, not replayed against a running instance, and CI/deployment descriptors outside the project were not visible.

## Residual risk

- Testcontainers 1.20.1 (test scope) stays pinned outside the Boot 4.1.1-managed 2.0.5 line; plan the 2.x move separately.
- /actuator/health/liveness and /actuator/health/readiness are new anonymous endpoints (via anyRequest().permitAll()); decide whether that is acceptable.
- JacksonConfig's tools.jackson ObjectMapper bean is not the mapper Spring MVC uses on Boot 4 (Boot's @Primary JsonMapper is); NON_NULL output now relies on spring.jackson.default-property-inclusion in application.yml.
- Re-adding an H2 console module on Boot 4 would bring back the anonymous /h2-console exposure through anyRequest().permitAll(), which predates the migration.
- CI/deployment descriptors outside the project and the eclipse-temurin:21-jre image were not built or inspected.
