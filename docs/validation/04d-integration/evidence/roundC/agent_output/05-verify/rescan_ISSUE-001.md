## 2. Reasoning

The collectors' worktree applied the fix diff cleanly this run (worktree.applied: true in all three facts bundles; 6 patched files materialized). None of the four Detection Notes signatures appears in the patched files: pom.xml now declares spring-boot-starter-parent <version>4.1.1</version> and <java.version>21</java.version>, the explicit maven-compiler-plugin <source>17</source>/<target>17</target> pair is gone and replaced by <release>${java.version}</release> (so no stale override keeps compiling at 17 — the catalog anti-pattern of a property edit overridden elsewhere does not apply), and the Dockerfile base image is eclipse-temurin:21-jre. Because the declared version matches the requested target (4.1.1, not 'latest'), the migration-specific STILL_VULNERABLE rule does not trigger. The absent signatures were not taken as proof on their own: the mechanism the root cause describes is that the parent's dependency management selects every managed Spring version, so I checked the resolved platform independently in my own throwaway worktree (fix diff applied as-is to HEAD 4935149, Maven 3.9.9 on JDK 21.0.11): mvn help:evaluate project.parent.version = 4.1.1, and mvn dependency:tree resolves 50 org.springframework.boot artifacts, every one at 4.1.1 and none at 3.x, with spring-core/spring-webmvc 7.0.9, spring-security-core/web 7.1.1, hibernate-core 7.4.5.Final, tools.jackson jackson-databind 3.1.5 and tomcat-embed-core 11.0.24 — the resolved-tree confirmation the CWE-1104 canonical approach requires, and consistent with 04D's own C4 evidence. The project has no <dependencyManagement> import or other BOM that could pin a Boot 3.x artifact back in. The language level is moved in all three places the root cause named (java.version, compiler config, runtime image), so the end-of-support platform selection itself is removed, not just today's literal strings. 04D's Migration Status (PARTIAL PASS) was treated as evidence, not inherited: its open blocking condition concerns framework-owned response shapes, not whether the platform version moved, and is assessed by the behavior guard.
