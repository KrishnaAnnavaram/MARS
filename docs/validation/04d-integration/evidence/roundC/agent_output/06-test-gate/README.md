# Additional Test Execution — QA + Build Gate

Deterministic gates run by **`06_additional-test-execution`** against every fix a diff was drafted
for (Compiled or Compile Failed alike — both gates compile the module themselves, independently of
the Fix Generator's own separate check):

- **QA gate** (`qa_<id>.md`) — drafts one new regression test (mocked, not database-backed — this
  repo has no embedded-MongoDB dependency) and runs it inside an isolated `git worktree`.
- **Build gate** (`build_<id>.md`) — runs `mvn verify` plus a dependency-tree diff inside another
  isolated `git worktree`. **No agent-authored content at all** — every line comes straight from
  the gate script (deterministic CI/CD execution, not open-ended agentic reasoning).

## Reading Status

- **Passed** — ran for real and exited 0.
- **Failed** — something exited non-zero, or the patch/test diff didn't apply. Never overridden.
- **Refused** — the linked fix report's Status was `Refused` (the Fix Generator never drafted a
  diff at all).

A `SKIPPED` individual QA test inside a Passed report means this sandbox lacks the dependency that
test needs (commonly a live MongoDB) — it is not counted as a failure, but it is not a pass either.
A build **Failed** whose errors sit outside the fix's own changed files may be this machine's known
JDK/Lombok toolchain mismatch — cross-check before blaming the patch.
