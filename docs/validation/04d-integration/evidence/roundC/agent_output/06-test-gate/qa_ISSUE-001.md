## 1. What the new test proves

Locks in the two runtime contracts the Spring Boot 3.5.0/Java 17 -> 4.1.1/Java 21 migration rewrote by hand-off to OpenRewrite (migration report section 0.3): I5 (JSON handling, Jackson 2 -> Jackson 3 JacksonConfig) and I6 (actuator health types relocated to org.springframework.boot.health.contributor). Against the migrated JacksonConfig ObjectMapper it asserts: a benign, fully populated EmployeeResponse serializes LocalDateTime fields as ISO-8601 strings ('2024-01-15T10:30:45', not timestamp arrays) on a single line; the adversarial sparse payload (every optional field null, the shape the 'create employee without department omits null' probe depends on) omits the null properties instead of writing null; an ErrorResponse carrying a nanosecond-precision timestamp is still truncated to the retained @JsonFormat 'yyyy-MM-dd'T'HH:mm:ss' pattern (the recipe proposed removing it and that proposal was rejected); and an ISO date round-trips back into LocalDateTime. Against the migrated DatabaseHealthIndicator it asserts UP with database/status details for an open connection, DOWN with 'Connection failed' and the recorded exception (not a thrown error) when the DataSource refuses a connection, and UNKNOWN for a closed connection. The test is written against the target APIs (tools.jackson.databind.ObjectMapper, org.springframework.boot.health.contributor.Health/Status), so it cannot compile on the pre-migration Boot 3.5.0/Jackson 2 code; on the migrated code it fails if Jackson 3 stops applying NON_NULL or ISO dates, if the @JsonFormat pattern is lost, or if the relocated health indicator changes its status/detail contract.

**Mocking strategy:** No Spring application context and no database. The ObjectMapper is obtained by calling new JacksonConfig().objectMapper() directly, and DTOs are serialized/deserialized in memory (asserted through a Map read-back, avoiding the renamed Jackson 3 JsonNode text accessors). The DataSource, Connection and DatabaseMetaData behind DatabaseHealthIndicator are Mockito mocks (spring-boot-starter-test), so neither H2, PostgreSQL nor Testcontainers is needed.
