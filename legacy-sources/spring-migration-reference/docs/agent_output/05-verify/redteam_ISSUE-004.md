## Residual risk

- ExcelUploadImpl.isValidExcelFile() validates only the client-supplied Content-Type header, not the file's actual structure -- this endpoint has no defense-in-depth independent of whichever POI version happens to be pinned. A future POI CVE (or one not yet disclosed) would be equally reachable through this same code path with no secondary check to catch it.
- Only employee-service's direct pin was addressed -- a transitive vulnerable poi dependency elsewhere in the workspace was out of scope for this fix and this red-team pass alike.
